# Typography: 文字の基礎設計

## 1. 状態と範囲

- 状態: UI書体Noto Sans JPと本文・説明文の字間0.04emはユーザー承認済み。サイズ・ウェイト・行間と数値専用書体は未確定。
- 目的: 写真の色を分析するUIで、日本語・英数字・単位・色コードの見え方を揃える。
- 背景: 既存実装は英数字にGeistを指定しているが、日本語は端末の代替書体に依存する。
- 正本: 本文の役割・用途・制約。比較見本はpreview.htmlに生成する。
- 実装は別の変更で行う。承認済みの書体と本文字間に実装が従う。残る文字組は役割別の見本で確認する。
- ライト／ダークで書体や字間を切り替えない。配色のメタファーだけで書体の用途を決めない。

## 2. 採用書体と比較候補

| 案  | 日本語の本文・操作  | 見出し              | 比較の意図                     |
| --- | ------------------- | ------------------- | ------------------------------ |
| A   | Noto Sans JP        | Noto Sans JP        | 整った作業台の基準             |
| B   | Zen Kaku Gothic New | Zen Kaku Gothic New | 柔らかさと読みやすさの両立     |
| C   | Noto Sans JP        | Noto Serif JP       | 見出しだけに上品な表情を加える |

- 採用: AのNoto Sans JP。本文・操作名・見出し・補足で共通に使い、ライト／ダークで同じ書体を保つ。
- 背景: 配色の雰囲気を保ちつつ、写真分析の操作と説明を安定して読める書体としてユーザーが選択した。
- B・Cは比較時の候補として残す。見本の切り替えは採用仕様を変更しない。
- 上の印象はIroMapへの適用に関する提案であり、フォント作者がIroMapへの適性を保証するものではない。
- Cの明朝は領域見出しに限る。ボタン・入力・軸・数値を明朝へ一括変更しない。
- 数値・色コードは共通のGeist Monoで比較する。最終的な数字書体は未確定。
- 写真やデータ色に実装上のフォント設定を混ぜず、ラベルの可読性を独立して扱う。

## 3. 役割別の基準案

| 役割               | サイズ | ウェイト | 行間 | 字間   | 目的                         |
| ------------------ | ------ | -------- | ---- | ------ | ---------------------------- |
| 領域見出し         | 18px   | 700      | 1.5  | 0.02em | 情報のまとまりを識別する     |
| 本文・説明         | 16px   | 400      | 1.75 | 0.04em | 日本語の続きと改行を読み取る |
| 操作名・入力ラベル | 14px   | 500      | 1.5  | 0em    | 短い語をすぐ認識する         |
| 補足・単位         | 14px   | 400      | 1.6  | 0.02em | 控えめでも読める             |
| 数値・色コード     | 14px   | 400      | 1.5  | 0em    | 桁・符号・小数点を識別する   |

- この表は比較の初期値。本文・説明文の字間0.04emだけを承認済みとし、その他の数値は未確定。
- 字間は文字の間、行間は行と行の間、余白は別の要素同士の間。密度の問題を字間だけで解決しない。
- 日本語の本文・説明文の字間は0.04em。見本の「説明文の字間」で0・0.02em・0.04emを比較し、ユーザーが0.04emを選択した。
- 字間は文字サイズに比例する。16pxでは0.64px。操作名・数値の字間は別の役割として検討し、この選択を一括適用しない。
- 操作名はまず0em。単語がばらばらに見えるほど開かない。
- 数値・コードは0em。文字の間隔を広げて見た目を整えず、列・小数点・単位の配置で揃える。
- 見出しの階層はサイズ・ウェイト・余白で表す。すべてを太字や大きな字間にしない。
- スマホでも情報量のために本文を一律に縮めない。タッチ領域の寸法はフォントサイズと別に決める。

## 4. 数値とフォールバック

- 数値は桁揃えを優先し、等幅数字または等幅書体を選ぶ。
- 比較する文字: 0・O、1・I・l、小数点、負号、%・°、HEX、RGB、HSL、Lab。
- 日本語を等幅欧文フォントへ強制しない。日本語の単位・説明はUI書体で表示する。
- 書体が取得できない場合でも文字を読めるフォールバックを残す。
- 比較見本は読み込み状況を表示し、取得できていない書体を確認済みとして扱わない。
- 配信方式、必要ウェイト、字種の分割、ライセンス同梱は実装時に決める。比較ページの外部読み込みを本番仕様にしない。

## 5. レビュー観点

- 「写真を選ぶ」「選択色の高さへ移動」「色の分布」の短い語が一目で読めるか。
- 同じ配色・サイズ・内容で比較し、フォントの違いを色や装飾の差と混同しない。
- 文章の字間を開くことで読みやすくなるか、間延びするか。
- 細い文字がダークで弱く見えないか。補足を小さく・薄くするだけで階層を作らない。
- 日英混在、長いファイル名、数値の列、200%文字拡大で崩れないか。
- フォントが読み込まれる前後で、ボタンの意味や情報の順番が変わらないか。
- 見出し・本文・操作・数値の役割を確定してから、全体の余白と密度を調整する。
