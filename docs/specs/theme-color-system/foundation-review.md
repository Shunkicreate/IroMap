# UI Foundation Review: 基礎として決める項目

## 1. 目的と範囲

- 色だけではデザインシステムは完成しない。情報・操作の設計を部品と画面へ落とす判断基準を揃える。
- 以下は検討項目と順序。未承認の値を確定事項として扱わない。
- 配色、Noto Sans JP、本文字間0.04emは承認済み。残る文字組とUI基礎は主要作業のワイヤーフレーム・部品例で確認する。
- 今回の色ルールのPRに残りすべてを追加することは前提にしない。アプリ実装は別の変更で行う。

## 2. 先に決める基礎

### 文字

- 目的: 名称・説明・数値を迷わず読む。
- 内容: 日本語と欧文の書体、役割ごとのサイズ・ウェイト・字間・行間、数値と単位、フォールバック。
- 判断材料: typography.mdと同じ配色の比較見本。

### 余白と密度

- 目的: 関係の強い情報を近くに置き、視線の往復を短くする。
- 内容: 部品の内側、関連項目間、領域間の余白。標準の情報密度。
- 基準案: 4px刻みを候補にし、内側8〜12px、関連項目8〜16px、領域間24〜32pxで比較する。
- 未確定: 広い画面の空き面積を、そのまま要素間の距離へ変換しない。

### 境界と形

- 目的: 操作範囲・情報のまとまり・重なりを識別する。
- 内容: 角丸、線の太さ、装飾線と操作線の使い分け、影を使う場所。
- 基準案: 小さな操作4〜6px、領域8px程度の角丸。通常面は線で区切り、影は重なる面を中心に比較する。
- 未確定: 値は作業画面で確認する。全領域を独立したカードにしない。

### 操作部品の寸法と表現

- 目的: 同じ操作を同じ見え方・操作感で扱う。
- 内容: ボタン、入力、タブ、スライダー、開閉、通知、ツールチップ、アイコン。
- 基準案: 主要なタッチ操作44pxの高さ。ラベル、値、単位、スライダーを近接させる。
- 未確定: 細かい入力と主要操作を同一の大きさにしない。

## 3. 画面と操作で決める基礎

### 選択・ホバー・フォーカス

- 目的: 一時的な指示、確定した対象、キーボードの位置を区別する。
- 内容: 線・形・文字・色の組み合わせ、強調の優先順位。
- 既存の状態設計を正本とし、装飾の都合で挙動を変更しない。

### 配置と画面幅

- 目的: 3D・断面・スライダーの反復参照を支える。
- 内容: 領域の最小寸法、最大幅、4K・ウルトラワイド、スマホ、スクロールと写真の一時表示。
- 確認済みの方向: スマホは3Dと断面を正方形に近い形で縦に並べる。広い画面でも主要操作を両端へ引き離さない。

### 動きと質感

- 目的: 操作のつながりを伝え、探索を妨げない。
- 内容: ホバー・開閉の時間、動きの削減、透明・ぼかし・影の採否。
- 未確定: Liquid Glass。先に不透明な面と静的な状態で確認する。

### 空・処理中・利用不可の見え方

- 目的: 今できることと、待つ理由・結果の意味を説明する。
- 内容: 既存の状態に対する文字・部品・配置の実例。
- 状態遷移や新しい通知をここで増やさない。既存の情報・状態設計に従う。

## 4. 決める順序

- 色 → 文字 → 余白と密度 → 境界と部品 → 主要画面の配置 → 動きと質感。
- 各基礎の単体見本と、写真を選んで3D・断面を往復する画面の両方で確認する。
- 全体のワイヤーフレームは並行して進める。全画面の実装を待ってから配置を初めて判断することは避ける。
