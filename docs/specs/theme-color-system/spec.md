# Feature Spec: テーマの色と文字の基礎ルール

## 1. 背景

- 写真の色を分析する作業台として、UIの色と分析対象の色を区別する。
- ライトは#FDD9D9よりさらに淡く上品な桜。背景は白に寄せすぎず、彩度を抑える。「操作と選択」の淡い色を好みの基準とする。ダークは夕景写真上部の紺を起点に青みを保ち、ベースの明度を下げる。アクセントは控えめにし、桜と抹茶・夕暮れと金星のような色の関係も設計する。これはユーザー指定。
- 従来の青系テーマを前提にせず、ベース・メイン・アクセントの用途から定義し直す。
- 配色の基礎ルールと比較見本はユーザー承認済み。UI書体Noto Sans JPと本文・説明文の字間0.04emもユーザー承認済み。残る文字組とアプリ本体への適用は別に扱う。

## 2. スコープ

### In Scope

- FR-1: 両モードのベース・メイン・アクセントと使用範囲を定義する。
- FR-2: 面、文字、境界、操作、選択、フォーカス、利用不可、通知の色を定義する。
- FR-3: 写真・色見本・3D・断面の色をテーマによって変えない。
- FR-4: 実際に隣接する組み合わせでコントラストを検証し、両モードの色見本を用意する。
- FR-5: 設計を正本にし、後続の実装が意味トークンに従う。
- FR-6: 両モードのUI書体をNoto Sans JP、本文・説明文の字間を0.04emとし、見本の初期表示も一致させる。

### Out of Scope

- アプリ本体へのCSS適用、画面配置・状態遷移・表示文言の再設計。
- Liquid Glass、透明な分析面、背景装飾グラデーションの採用判断。
- 画像の色管理、モニター校正、HDR対応。
- 新しい通知や操作の追加、テーマの初期値・保存方法の変更。

## 3. 利用者と作業

- 写真の一点を選び、3Dと断面を往復しながら色の位置と方向を調べる人。
- ライト／ダークで操作の意味が変わらず、分析対象の色がUIの装飾に埋もれないことを求める。

## 4. 受け入れ条件

### FR-1

- 両モードに三役の色値・目的・背景・使用箇所・禁止箇所と、色の関係を説明するメタファーがある。アクセントは主操作より小さな面積に限定する。
- 色の面積比を機械的な60・30・10配分にしない。写真・データの色はUI配分から除外する。

### FR-2

- 通常・ホバー・押下・選択・フォーカス・利用不可・意味を持つ通知を区別する。
- 色だけで状態を示さない。選択には形、通知には名称・アイコン等を添える。
- 装飾境界と入力・操作の識別に必要な境界を区別する。

### FR-3

- 観察面は無彩色・不透明。写真や点群をブランド色で染めない。
- 同じデータのRGB値を両モードで保持する。観察面の明るさは変わるため、知覚が同一になるとは保証しない。
- 任意の画像上の選択点は明暗の二重輪郭で表示する。点群・断面のデータ色は選択強調で塗り替えない。

### FR-4

- 通常文字4.5:1、操作識別に必要な境界・図形3:1を下限として検査する。
- 丸める前の比率で判定する。免除可能な利用不可の文字も本案では4.5:1を目標にする。
- 代表背景・操作状態・通知面・観察面の色対を記録する。
- 数値検証と視覚レビューを区別し、完全なWCAG準拠を宣言しない。

### FR-5

- 色値の正本はtokens.json、意味と制約の正本はdesign.md。プレビューと測定表は正本から生成する。
- 既存CSSやライブラリの変数名は下流の対応表で扱い、設計の色名を実装都合で変更しない。
- 設計と現行実装の一時的な差分を許容する。

### FR-6

- typography.mdを文字ルールの正本とし、実装が従う。比較見本は採用値を初期表示する。
- 操作名・数値の字間、文字サイズ・ウェイト・行間、数値専用書体は今回の承認に含めない。
- 外部フォントの読み込み結果と代替表示を区別する。比較用の配信方法を本番仕様として扱わない。

## 5. 未決事項

- 色の基礎ルールは承認済み。実画面での調整と検証は実装時に行う。
- 桜の濃さ、ダークの面の明るさを実際の作業画面で調整する範囲。
- テーマの既定値は今回決めない。
