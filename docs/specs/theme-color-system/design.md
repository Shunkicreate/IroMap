# Design: 桜と抹茶、夕暮れと金星の色ルール

## 1. 確定している方向と正本

- ライトは#FDD9D9よりさらに淡く、上品な桜。背景も桜色を感じられる明度にし、白に寄せすぎない。「操作と選択」の淡い色を基準に背景の彩度を抑える。
- ダークは提供された夕景写真の上部の紺を起点に、青みを保ちながらベースの明度を下げる。
- アクセントは主操作より控えめにする。色の関係は「桜と抹茶」「青い夕暮れと金星」を手がかりにする。
- 配色の基礎ルールと比較見本はユーザーのLGTMで承認済み。アプリ本体への適用と実画面での確認は別の変更で行う。
- [文字の基礎設計](typography.md)ではNoto Sans JPと本文・説明文の字間0.04emをユーザー承認済み。その他の文字組は未確定。[残るUI基礎の検討項目](foundation-review.md)は未確定。
- 正本: 本文の意味・制約と[tokens.json](tokens.json)のsRGB HEX値。測定表とプレビューは生成資料。
- 上位方針: [デザインの土台](../../product/design-foundation.md)。情報の優先度と操作は既存の[情報設計](../workbench-information-architecture/information-architecture.md)・[状態設計](../workbench-information-architecture/state-transitions.md)に従う。
- 依存方向: 上位方針 → 色ルール・意味トークン → 部品仕様 → 実装。現行CSSは正本ではない。

## 2. ベース・メイン・アクセント

| 役割       | ライト：桜と抹茶 | ダーク：夕暮れと金星 | 目的                                         |
| ---------- | ---------------- | -------------------- | -------------------------------------------- |
| ベース     | #F6EFF0          | #041A35              | 広い背景。桜色の空気と、青が感じられる夕紺   |
| メイン     | #FCE6E8          | #A6C8F0              | 主操作の塗り。淡い花びらと、夕暮れの明るい空 |
| アクセント | #E7EDDF          | #EAE1C4              | 少量の添え色。淡い抹茶と、金星の柔らかな光   |

- 三色の面積を固定比率にしない。写真・点群・断面の色はUI配分から除外する。
- 面積と視覚的な強さを別に扱う。明るい金星色は小さくても目立つため、点や短い注記に限定する。
- 三色の等幅・等面積の使用を画面へ転用しない。見本でもアクセントのスウォッチを小さくする。
- メインとアクセントは役割が違う。アクセントを主ボタン・確定選択・フォーカスへ広げない。
- 成功・警告・エラー・情報は別の意味色。ブランドの添え色を通知の意味の代用にしない。

## 3. メタファーを配色と用途へ結びつける

### ライト：桜と抹茶

- 背景: 白い紙の上に花びらを置くのではなく、画面全体に淡い桜の空気を作る。ベース#F6EFF0は桜の気配を残した低彩度の面。「操作と選択」のパネル#FFF8F8と主操作#FCE6E8は、ユーザーが好んだ色の基準として維持する。
- メイン: 花びらの薄い色#FCE6E8。参考#FDD9D9より赤みの密度を抑え、濃いローズの面を主役にしない。
- 抹茶: 甘い桜の印象を少量の落ち着いた緑で整える。静かな補助の注記に使い、成功や選択という意味を勝手に付けない。
- 上品さ: 低彩度の面、暗い柔らかな文字、平面の色、少ない添え色で表す。強い花柄、金の縁、光沢を必須にしない。
- 主操作文字は#55383D、輪郭は#915E6A。淡いピンクに白文字を重ねない。
- ホバー#F9DCDF、押下#F3CDD3。桜色の範囲で少し深め、別の強い色へ飛ばさない。

### ダーク：青い夕暮れと金星

- 背景: 写真上部の横25・50・75%、縦5・10・15・20%の12点で#001526〜#00223B付近の紺を確認した。
- 写真の参照点#001727は横50%・縦5%。UIは青みを感じられる色へ展開し、さらに「ベースの明度を下げる」という指示に沿って#041A35を使う。パネルと主操作の値は維持し、広い背景を暗くする。写真から取得した値と、設計で調整した値を区別する。
- パネル#061D38、重なる面#092542、ホバーの面#0D2C4B。青みを保ちつつ明度を抑え、ベース#041A35から浮きすぎない階層にする。主操作と選択の色は維持する。
- メイン#A6C8F0: 同じ青の系列を明るくし、暗い環境でも主操作を識別する。
- 金星#EAE1C4: 橙の夕焼けの帯ではなく、青の中に小さく見える淡い光。小さな補助記号や短い注記に絞る。
- 金星色の大きなボタン、広い黄色のパネル、発光、星空の装飾を標準にしない。点のような小さな面積でニュアンスを作る。
- 写真は2026_DSC04642_edited.jpg、元画像5296×3530 px。画像はリポジトリへ追加しない。参照RGB値は校正された測色値の主張ではない。

### メタファーの境界

- 桜・抹茶・夕暮れ・金星は、配色と面積・強弱の関係を決める手がかり。画面の機能名やユーザーへの説明文を置き換えない。
- 「桜だから選択」「金星だから保存」等の恣意的な機能対応は作らない。
- 抹茶・金星の色がなくても主要な色分析を完了できる。情報に必要な意味がある場合は名称や形でも示す。

## 4. 面・文字・境界

- surface.canvas: 広い背景。桜・夕暮れの基調を担当する。
- surface.panel: 操作・情報領域の不透明な面。
- surface.raised: メニュー・ポップオーバー・ダイアログ等の重なる面。
- surface.hover: 中立操作の一時的な反応。確定選択と区別する。
- text.primary: 見出し・本文・数値・操作名。
- text.secondary: 補足・単位・説明。重要度が低くても読める。
- border.subtle: 装飾的な区切り。入力の識別に必要な境界へ流用しない。
- border.control: 入力や操作範囲の識別に必要な境界。
- action.border: 主操作の輪郭。淡い塗りのライトでは、塗りと周囲の両方に対して識別できる濃さを持つ。
- attention.text／border: 添え色の上や注記に必要な文字・輪郭。淡い緑の塗りと暗い緑の文字を分ける。
- 透明な面、発光、装飾グラデーションを標準にしない。色の役割を平面で確認する。

## 5. 部品への割り当て

| 情報・部品               | 色                                          | 目的・併用する表現                                                    |
| ------------------------ | ------------------------------------------- | --------------------------------------------------------------------- |
| 全体・ヘッダー           | surface.canvas、text.primary                | 広い基調と識別                                                        |
| 操作領域・詳細           | surface.panel、text.secondary               | 情報の開示階層は情報設計に従う                                        |
| 主ボタン                 | action.primary／onPrimary／border           | 淡い塗りと読める文字、識別できる輪郭                                  |
| 補助ボタン・入力         | surface.panel、border.control、text.primary | 操作範囲の識別                                                        |
| 主操作のホバー・押下     | action.primary.hover／pressed               | 同じ系列で深さを変える                                                |
| 選択したタブ・項目       | selection.surface／text／border             | 境界・下線・選択記号も添える                                          |
| スライダー               | selection.border、border.control            | アクティブ部分は識別できる濃さ。つまみの面はmain、輪郭はaction.border |
| キーボードフォーカス     | focus.ring                                  | 2px以上の外周と2pxの間隔。塗り操作には面色の隙間を設ける              |
| 利用不可                 | disabled.surface／text                      | 理由と不活性の属性。全体のopacityを下げない                           |
| 補助の注記・小さな印     | attention.surface／text                     | 抹茶と金星の添え色。主操作より小さく、塗りボタンにしない              |
| 通知                     | feedbackの色と対応surface                   | 成功・警告・エラー・情報の名称等を添える                              |
| 写真・3D・断面           | observation.surfaceと実データ色             | UIのブランド色から切り離す                                            |
| 図のラベル・補足・ガイド | observation.text／secondary／guide          | 観察面に対して読み取れる                                              |
| 観察面の選択枠           | observation.selection                       | 無彩色の面上に使用する                                                |
| 任意色上の選択点         | selectionMarker.inner／outer                | 白と暗色の二重輪郭。位置・形・値も示す                                |
| 色見本と値               | 元のデータ色、通常の文字色                  | テーマに依存しないRGB値とコード                                       |

- 添え色は必要な補助情報にのみ使う。飾りの点やバッジを全項目へ追加しない。
- 添え色のhover／pressedは注記に付属する操作が必要な場合の予約値。主ボタンの系列として使わない。
- 通知色は既存の通知を表現するためのもの。画像差し替え失敗の専用通知を追加しない。
- 本表は色の割り当て。情報の優先度や状態遷移を変更しない。

## 6. 色観察の領域

- 桜・抹茶・紺・金星は外側のUIに使う。写真・3D・断面の内側は無彩色・不透明。
- ライトの観察面#E6E6E6、ダークの観察面#242424。R=G=B。
- 周囲の明度はテーマで変わるため、同じRGBでも知覚が変わり得る。値の保持と知覚の一致を混同しない。
- 写真の白バランス、点群・断面・色コードはテーマ変更で変換しない。
- データを表すグラデーションは許可する。UI装飾とは区別する。
- 任意色上の選択は白と暗色の二重輪郭にし、ブランド色だけで強調しない。
- 写真や図形に文字が重なる場合は、不透明なラベル面で背景を固定する。

## 7. 値と検証の管理

- tokens.json: 両モードで同じ意味トークンのキーを使う。不透明な6桁sRGB HEX。
- design.md: 意味・目的・背景・禁止事項。
- palette.md、contrast-report.md、preview.html: render-preview.mjsから生成する。直接編集しない。
- 再生成: リポジトリルートでnode docs/specs/theme-color-system/render-preview.mjsを実行する。続けてpnpm --dir web exec prettier --write ../docs/specs/theme-color-system/palette.md ../docs/specs/theme-color-system/contrast-report.md ../docs/specs/theme-color-system/preview.htmlで整形する。
- 通常文字4.5:1、操作識別に必要な境界・図形3:1を下限として、丸め前の値で判定する。
- 淡い塗りで隣接面との3:1を確保できない場合、輪郭を隣接面と塗りの両側に対して検査する。
- 基本の文字、主操作・添え色の通常／ホバー／押下、通知、入力・選択・フォーカス、観察面を検査する。
- 装飾線の低コントラストは許容する。入力や選択の識別境界には使わない。
- 数値検査は配色の一部。実際の部品寸法、重なり、キーボード操作、実画像の見え方は実装時に確認する。

## 8. 根拠

- [Material Design: Color roles](https://m3.material.io/styles/color/the-color-system): 役割に色を割り当てる考え方を参照する。具体値とメタファーはIroMapの提案。
- [WCAG 2.2: 文字のコントラスト](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html): 通常文字4.5:1、判定前に丸めない。
- [WCAG 2.2: 非テキストのコントラスト](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast): 操作の識別に必要な図形・境界等は3:1。
- [WCAG 2.2: 色の使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html): 色だけで意味を伝えない。
- ユーザー指定: #FDD9D9より淡い上品な桜、白に寄せすぎない桜の背景、青みを保ち明度を下げた紺、背景の彩度を抑えた桜、控えめなアクセントと自然な色の関係。
