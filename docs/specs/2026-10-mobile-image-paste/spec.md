# Feature Spec: スマホの画像貼り付け（Issue #86）

## 背景とスコープ

iPhone の Safari で note の JPEG を別タブで開いてコピーし、Brave の IroMap で貼り付けボタンを押すと失敗した。
iOS のアプリ間ペースト許可を承認した後も、現行 UI は「読み取りが許可されていません」と表示した。
画像ファイルをブラウザが提供する場合の取り込みを改善する。URL からの画像取得は対象外。

## 機能要求

### FR-1: 画像ファイルの取り込み

- paste イベントの items と files の両方を調べ、最初の取得可能な画像を適用する。
- MIME が空でも既知の画像拡張子があるファイルを受け入れる。
- 同じ paste イベントによる画像適用・通知は一度だけ行う。

### FR-2: iPhone の標準ペースト操作

- 長押し「ペースト」を実行できる編集可能な入力欄を提供する。
- 貼り付けた HTML やテキストを入力欄に挿入しない。

### FR-3: 貼り付けボタン

- 読み取りをクリックのユーザー操作中に開始する。
- PNG を優先し、形式の取得が失敗した場合は残りの画像形式・項目を試す。
- 画像がない場合と画像取得に失敗した場合を区別する。

### FR-4: 許可後の失敗からの復帰

- read のアクセス失敗と getType の画像データ取得失敗を区別し、許可拒否と断定しない。
- 失敗時はその場に標準ペースト・ファイル選択による復帰方法と入力欄への移動ボタンを表示する。
- 成功した貼り付けやファイル選択で復帰案内を消す。読み取り中だけ貼り付けボタンを無効化する。
- 失敗段階と例外名を開発者コンソールに残す。クリップボード本文や画像・URL は記録しない。

## 制約と未決事項

ブラウザが URL だけを提供する場合やアクセスを拒否する場合は画像を取得できない。
対象画像は有効な JPEG（4000×2667、558131 バイト）。iOS/Brave のバージョンと実機での失敗段階は未確認。
報告時の #87 プレビューにはこの修正がない。解消判定には #86 の最新プレビューで iPhone 実機確認が必要。
