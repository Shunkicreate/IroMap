# Feature Spec: スマホの画像貼り付け（Issue #86）

## 背景とスコープ

iPhone の Safari で note の JPEG をコピーし、Brave の貼り付けボタンで読み取ると失敗した。
ユーザーの実機確認では、編集可能な入力欄から OS のペーストを実行すると成功した。
この成功経路へ入口を統一し、画面の説明と装飾を減らす。URL からの画像取得は対象外。

## 機能要求

### FR-1: 画像ファイルの取り込み

- paste イベントの items と files の両方を調べ、最初の取得可能な画像を適用する。
- MIME が空でも既知の画像拡張子があるファイルを受け入れる。
- 同じ paste イベントによる画像適用・通知は一度だけ行う。

### FR-2: 標準ペーストへの統一

- 「貼り付け」をボタン風の編集可能領域として提供し、OS の標準ペーストを受け取る。
- クリック時に navigator.clipboard.read を呼ばない。PC のキーボードペーストも同じ領域で受け取る。
- 貼り付けた HTML やテキストを挿入しない。入力文字も残さない。

### FR-3: シンプルな入力エリア

- 「選ぶ」「貼り付け」を同じ幅・高さで横並びにし、その下に画像プレビューを配置する。
- 通常表示から見出し、重複した説明、ファイル名を外す。画像情報は開いたときだけ表示する。
- 単色の面、薄い枠、小さめの角丸を使い、グラデーションと影を除く。
- 入力領域にフォーカスしたときだけ標準ペースト操作の案内を出す。
- 見た目を短くしても、スクリーンリーダー用の見出しと入力名は維持する。

### FR-4: 画像なしからの復帰

- paste イベントが画像を含まない場合は画像なしと表示し、ファイル選択を案内する。
- 成功した貼り付けやファイル選択で復帰案内を消す。
- クリップボード本文、画像、URL をログに記録しない。

## 制約と未決事項

元の JPG（4000×2667）のデコードと、実機での入力欄経由の貼り付けは確認済み。
ボタン風にした編集可能領域での iOS メニュー表示は実機で再確認する。
キーボードやカーソルが出る可能性と、長押しが必要かどうかは OS に依存する。
