# IroMap Design Foundation

状態: Draft / 方向性のレビュー用。ビジュアル承認・実装承認は未実施。
関連: [Issue #99](https://github.com/Shunkicreate/IroMap/issues/99)

具体化した設計: [作業と情報の関係](../specs/workbench-information-architecture/design.md)、[情報単位ごとの操作と状態](../specs/workbench-information-architecture/state-transitions.md)

2026-10-11の本人の作業説明を反映。写真は対象選択時、3D・断面は反復探索時に中心となる。
以下の大きさ・優先度は作業段階で判断し、画像を常に最も大きく表示する方針にはしない。

同日の追加決定: 確定色は一つで、新しい選択へスライスが自動追従する。前の色は保持しない。
スマホは3Dとスライスを正方形に近い図として縦に並べ、写真は点選択後も自動で閉じない。
Labを初期値にしない。再解析時は対象維持不要、差し替え失敗時は現在の作業を更新しない。
コピー内容の既定対象・書式の再設計は今回の情報設計から除外する。

## 1. この文書の役割

プロダクトとしての体験、表現、操作、品質の判断基準を揃える。色や部品の選定は、この基準から導く。
この文書はデザインシステムの上位方針であり、完成したコンポーネント仕様や承認済み画面ではない。

記述の区分:

- 確認済み: ユーザーの指示、Issue、現在のプロダクト方針に基づく。
- 提案: 今回の設計案。レビューで修正できる。
- 未確定: 判断に必要な材料が不足している。

## 2. 確認済みのプロダクト前提

- 中心となる作業は「写真・画像の色を分析する」。2026-10-11にユーザーが指定。
- Issue #99の中心は、IroMap専用のデザインシステムとUIコンポーネントを整えること。
- シンプルな表現、2026年の動向を踏まえた検討、AI生成テンプレートを連想させる表現の削減を求める。
- Liquid Glassの採用は慎重に検討する。ニューモフィズムも参考候補であり、採用は確定していない。
- GitHub mainのvision.mdは、写真の色分布・色距離・色面積比の可視化と、色構造の比較・説明を目指している。
- 色空間可視化は写真分析の基盤。3Dキューブ自体を最終的なコア価値にはしない。

参照したローカル実装は `.worktree/feature/issue-86-mobile-image-paste/web/src/`。
ルートのvision.mdはGitHub mainと内容が異なるため、古い方針を今回の前提として扱わない。
参照実装の画面を実機で確認した状態ではなく、コードから構造・文言・スタイルを調査した段階。

## 3. 利用者と、提供する価値

### 3.1 利用者の仮説

写真・画像を扱い、印象を色の分布や数値と結びつけて理解したい人。
職種、熟練度、利用頻度は未確定。プロの写真家だけを前提にしない。

### 3.2 中心となる問い

「この画像の色にはどんな特徴があり、どの部分がその特徴を作っているか」。

今回明らかになった主要シナリオでは、「写真のこの部分の色は空間のどこにあり、どの方向へ変えると望む色に近づきそうか」まで掘り下げる。
画像全体の統計は、必要な際の確認や外部AIへの相談を支える補助経路になる。

### 3.3 体験として提供する価値（提案）

画像の印象を、見える分布と、その根拠になる値に結びつける。
全体から気になる領域へ掘り下げ、結果を説明・持ち出しできるようにする。
画面上で色を観察することと、数値を分析することの両方を支える。

### 3.4 代表作業（提案）

| 作業                 | 開始時の問い                       | 作業後に得られるもの                     |
| -------------------- | ---------------------------------- | ---------------------------------------- |
| 写真から対象を選ぶ   | 現像で気になるこの部分はどんな色か | 対象位置、元の色、空間内の対応点         |
| 位置と周辺を探る     | どの方向へ変えるとよさそうか       | 3D・断面・軸の関係、周辺の色             |
| 元の位置を再確認する | 写真のどこを見ていたか             | 写真と選択点の対応                       |
| 全体の根拠を調べる   | 全体評価・相談にどんな情報が必要か | 指標・ヒストグラム、対象と条件付きの出力 |

複数画像の比較と診断コメントはvision上の方向性。初期デザインの必須機能かどうかは別途決める。
本草案から機能追加を自動的に確定しない。

## 4. プロダクトの性格と表現方向（提案）

方向: 「観察と検証を支える、整った作業台」。

| 性格           | 表現への落とし込み                               | 避けたい結果                   |
| -------------- | ------------------------------------------------ | ------------------------------ |
| 正確           | 対象・単位・条件・更新状態を明示する             | 見た目は精密だが値の意味が不明 |
| 落ち着いている | 安定した配置、控えめな境界、観察領域を囲む中立色 | 低コントラストで操作箇所が不明 |
| 探索しやすい   | 画像・分布・選択値を対応づける                   | 全機能を同じ優先度で並べる     |
| 親しみやすい   | 短い日本語、必要な場所で用語の意味を説明する     | 専門語の省略だけで情報を削る   |

「シンプル」は、情報の関係が分かり、次の操作を判断できる状態と定義する。
余白の多さや部品数の少なさだけで評価しない。

### 4.1 比較すべき表現方向

| 候補                             | 強み                                 | 検討すべき弱点                 |
| -------------------------------- | ------------------------------------ | ------------------------------ |
| 中立的な分析用作業台（基準案）   | 写真、分布、数値の対応を設計しやすい | 一般的な業務画面に見える可能性 |
| 写真を主役にする閲覧中心の表現   | 画像の特徴を見つけやすい             | 指標や比較が奥に隠れる可能性   |
| 計測器を参考にした操作中心の表現 | 数値と操作の精度を伝えやすい         | 専門家向けの印象が強まる可能性 |

同じ画像・同じ機能・同じ状態で比較する。新しい機能や装飾の量を変えて比較しない。
基準案の弱点には、色見本・座標・選択連動の一貫した表現でIroMapらしさを与える。
ロゴやブランド書体の最終判断は、画面構造と並行して行う別の検討事項。

## 5. デザイン原則と優先順位（提案）

判断が衝突した場合の順序:
分析内容の正確さ → 操作の到達性・可読性 → 作業の連続性 → 表現の一貫性 → 新しさ・装飾。

| 原則                     | 必要な設計                                                   | レビューで確かめること                   |
| ------------------------ | ------------------------------------------------------------ | ---------------------------------------- |
| 分析対象を常に把握できる | 画像名、全体／選択の区別、対象範囲を結果の近くに置く         | 指標がどの画像・範囲の値か説明できる     |
| 観察条件を安定させる     | 色見本と画像周辺の不透明な中立面、テーマ変更の影響範囲を定義 | 同じ色見本の値がテーマや装飾で変わらない |
| 表示同士の関係を見せる   | 同じ選択を画像・分布・値で対応させる                         | 選択した部分を別の表示でも識別できる     |
| 詳細は必要な場所で開く   | 基本操作と詳細設定を分け、結果の解釈情報を近くに置く         | 初回の画像入力が詳細設定に埋もれない     |
| 試して戻れる             | ホバーと確定選択を区別し、解除・再試行を提供                 | 一時的な指示で確定対象が失われない       |
| 状態を説明する           | 処理中、更新待ち、空、失敗、利用不可を区別                   | 古い結果を新しい条件の結果と誤認しない   |

中立面は色観察を支えるが、画面の校正や色管理の正確さを保証するものではない。
分析値、表示色、入力画像の色プロファイルの扱いは、検証可能な範囲を別途仕様化する。

## 6. 情報設計と画面の骨格（提案）

### 6.1 利用者に示す概念

- 対象画像: 今調べている画像。
- 対象範囲: 全体または選択領域。
- 分布: 色の位置、広がり、割合。
- 選択色: 確定した色と、その表現値。
- 分析条件: 色空間、固定軸、サンプリングなど、結果の意味に関係する条件。
- 結果: 指標・グラフと、その対象・条件・更新状態。

ホバー色、確定した色、選択領域は別の概念。表示上も混同しない。
領域選択が各指標へ及ぼす影響は実装監査が必要で、全パネル連動を既存挙動として断定しない。

### 6.2 体験の骨格

「画像を入れる → 全体を見る → 部分を選ぶ → 根拠を読む → 結果を持ち出す」。
固定の手順を強制するウィザードにはせず、観察と選択を往復できるようにする。

主要な反復経路は「写真の点を選ぶ → 3Dで位置を見る → 選択色の断面へ移る → 断面と3Dを往復する」。
全体指標の参照とコピーは必要に応じて分岐する。写真入力は一枚の作業で通常一度、写真の再確認は必要な際に行う。

### 6.3 画面領域

| 領域           | 役割                                                 | 優先度                                       |
| -------------- | ---------------------------------------------------- | -------------------------------------------- |
| アプリヘッダー | IroMapの識別、対象画像、全体に関わる操作             | コンパクトで安定した位置                     |
| 写真領域       | 入力、対象選択、対応位置の再確認                     | 対象選択中は主役、探索中は補助・一時表示候補 |
| 探索領域       | 3Dと断面・スライダーの反復参照                       | 探索中に最も大きな面積を配分                 |
| 選択情報       | 現在の唯一の選択色・対応位置の最小文脈、詳細への経路 | 探索中も参照可能。詳細コードは必要時に開く   |
| 分析結果       | 指標・ヒストグラム、コピー                           | 必要時に開く補助領域。機能は残す             |
| 詳細設定       | 3D表示・高度な分析条件                               | 参照頻度と設定頻度を分け、主作業から退避可能 |

キューブ、スライス、指標表を一律に等幅で配置する前に、主要な問いへの寄与で優先順位を決める。
どの分布を初期表示にするかは未確定。デザインだけで決めず、代表作業で比較する。

### 6.4 幅と入力方法

- 広い画面: 3D・断面・スライダーを近接させ、写真と分析を補助領域に展開できる構造を試す。
- 狭い画面: 3Dとスライスを正方形に近い図として縦に並べ、写真を一時表示する構造を試す。
- 同時表示できない場合は、表示切り替えで確定選択と分析条件を失わない。
- モバイルを縮小したデスクトップ画面として扱わない。タッチで選択・解除・入力に到達できる。
- ブレークポイントは領域の最小可読幅から決める。具体的な値はワイヤーフレームで検証する。
- 4K・ウルトラワイドでも主作業を画面両端へ引き離さない。物理解像度とブラウザの利用可能幅を区別する。
- 具体的な操作・状態・保持規則は [情報単位ごとの操作と状態](../specs/workbench-information-architecture/state-transitions.md) を正本とする。配置の比較候補は [作業と情報の関係](../specs/workbench-information-architecture/design.md) に置く。

## 7. 基礎表現の設計契約（提案）

### 7.1 色

役割を「UIの面と文字」「操作と状態」「分析対象の色」に分ける。
UIテーマ変更は分析値と実際の色見本を変更しない。グラフのガイド・ラベルだけは可読性に応じて切り替える。
図の色が何を符号化するかを明示し、実際の色表現とカテゴリを区別する。
画像の主色をUI全体のアクセントへ自動適用する案は、観察条件を変えるため初期基盤には採用しない。

ライトは#FDD9D9より淡く上品な桜で、背景も白に寄せすぎず彩度を抑える。「操作と選択」の淡い色を基準とする。ダークは夕景写真の紺を起点に青みを保ち、ベースの明度を下げる。添え色は「桜と抹茶」「夕暮れと金星」の関係で控えめに使う。外側のUIと、無彩色の観察面を分ける。
色の用途・具体値の提案は[テーマの色ルール](../specs/theme-color-system/design.md)と[tokens.json](../specs/theme-color-system/tokens.json)を正本とする。テーマの既定値は未確定。配色の基礎ルールはユーザー承認済み。実装、実画面での検証は別に行う。

トークンの責務:

| 層     | 定義するもの                   | 例                                             |
| ------ | ------------------------------ | ---------------------------------------------- |
| 基礎値 | 色の段階、余白、文字サイズなど | gray scale / spacing scale                     |
| 意味   | 面・文字・状態などの用途       | surface.canvas / text.secondary / state.error  |
| 部品   | 部品と状態への割り当て         | field.border.focus / button.background.pressed |

生の色値を機能CSSへ追加する前に、共通用途かデータ色かを判断する。
ライト／ダークで同じ意味を保ち、色番号だけを機械的に反転しない。

### 7.2 文字・数値・文言

- UI書体はNoto Sans JP、本文・説明文の字間は0.04em。両モードで共通に使う。採用事項と未確定の文字組は[文字の基礎設計](../specs/theme-color-system/typography.md)を正本とする。
- 短い操作ラベル、英数字、色コード、単位も同じサンプルで確認する。数値専用書体と残る文字組は未確定。
- 役割は見出し、本文、ラベル、補足、数値、コードに分ける。小さい文字で密度を稼がない。
- 数値は桁揃え、単位、精度、欠損、丸めを定義する。表示の丸めを内部値の変更と混同しない。
- 結果がない場合をゼロで表さない。未計算・対象なし・失敗を区別する。
- 操作は具体的な動詞、名称は同じ概念に同じ語を使う。
- 短い表現でも、軸名、単位、エラーから復帰するための説明を残す。
- 診断コメントを導入する場合は、観測値と解釈を区別し、根拠を参照できるようにする。

### 7.3 空間・境界・質感・動き

- 余白を、部品内部／関連項目間／領域間の階層で定義する。
- 境界線は対象や操作範囲の識別、影は重なり、角丸は部品群の整合のために使う。
- 画面をカードで埋めることを規則にしない。関係の強さを配置と間隔でも示す。
- 標準密度を先に決める。高密度モードの必要性は利用頻度と代表作業で判断する。
- 動きは状態のつながりを示す。分析値の演出によるカウントアップを初期仕様には入れない。
- 減速・削減設定でも状態が分かり、処理を待つためだけの装飾アニメーションを追加しない。

Liquid Glassとニューモフィズムは素材候補として保留。
採用検討は、不透明な基準案との同一条件比較で行う。画像・色見本・分析内容へ影響しないこと、背景が変わっても操作を読めること、効果を無効にしても状態が伝わることを条件にする。
Web上のぼかし表現とAppleのネイティブLiquid Glassは同等の実装とは扱わない。

## 8. 共通の操作・状態モデル（提案）

| 状態             | 表示する内容                                     | 提供する行動                   |
| ---------------- | ------------------------------------------------ | ------------------------------ |
| 画像なし         | 入力方法と、分析できる内容の短い説明             | 画像を選ぶ／貼り付け           |
| 読み込み・分析中 | 対象画像と処理中であること。分かる範囲の進行状況 | 利用可能な操作を維持する       |
| 結果あり         | 対象、条件、結果                                 | 選択／詳細／コピー             |
| 再計算中         | 更新中の条件と、既存結果が古いこと               | 現在値と結果の区別を保って観察 |
| 対象なし         | 有効な選択・サンプルがない理由                   | 選択解除／条件を戻す           |
| 失敗             | 失敗した対象・操作と復帰方法                     | 再試行／別の入力方法           |
| 利用不可         | 操作できない理由                                 | 対応可能な代替経路             |

補足:

- ホバーは一時表示、選択は確定表示。ホバー終了で確定色を消さない。
- スライダー操作中の表示値と、計算に適用済みの値を区別する。計算をいつ確定するかは部品仕様に明記する。
- コピーなどの短い通知は一時表示でよい。入力失敗など復帰が必要な情報は関連箇所に残す。
- 画像差し替えの失敗は上記の一般的な失敗表現の例外。現在の作業状態を更新せず、専用の失敗状態・追加通知を導入しない。
- 確定選択の変更時はスライスを自動追従させ、前の確定色を保持しない。画像再解析の成功時は選択を解除する。
- 非同期処理で新しい入力が来た場合、古い結果を現在の結果として見せない。
- 指標の説明と、操作方法の説明を分ける。重要情報をホバーだけに置かない。

## 9. デザインシステムの構成と運用（提案）

| 層         | 必要な定義                                                             |
| ---------- | ---------------------------------------------------------------------- |
| 原則       | 本文書の体験・表現・判断優先順位                                       |
| 基礎       | 色、文字、数値、余白、サイズ、境界、重なり、動き、テーマ               |
| 共通部品   | ボタン、入力、タブ、チェック、スライダー、開閉、ツールチップ、通知     |
| 分析用部品 | 色見本と値、軸入力、指標、グラフ枠、画像入力、選択情報                 |
| パターン   | 画像入力、全体観察、領域選択、条件更新、結果の説明、持ち出し、失敗復帰 |
| 画面       | 代表作業・状態・幅での組み合わせ                                       |

各部品の仕様は、用途、使わない場面、構造、種類、全状態、キーボード／タッチ、文言、トークン、実例、検証項目を持つ。
見た目だけの部品一覧では承認可能な仕様としない。

既存のRadix等の操作基盤を活かし、IroMap独自の表現と契約をその上に定義する案を基準とする。
基盤ライブラリの選択と、ブランド表現の選択を混同しない。

共通規則の変更は、用途と理由、影響する部品・画面、検証結果を記録する。
一画面だけの例外は名前と理由を残し、共通部品の変種にする必要があるかレビューする。
承認者と最終的な保存先は未確定。新しい基盤はDraft、Reviewed、Adoptedの段階を明示する。
実装へ進む際はdocs/specs以下で要求・設計・タスク・受け入れを対応づけ、旧UI基盤仕様との変更点を記録する。

## 10. 「AIっぽさを減らす」の判定（提案）

生成元を判定する言葉として使わず、今回避けたい画面上の結果へ分解する。

| 見直し対象                     | 判定する問い                                 |
| ------------------------------ | -------------------------------------------- |
| 宣伝的な大見出し               | 作業画面で利用者の判断に役立つか             |
| 装飾グラデーション・発光・透過 | 対象・状態・階層を説明する役割があるか       |
| 等価なカードの反復             | 内容の重要度と作業上の関係を表しているか     |
| 説明文の反復                   | 操作・解釈・復帰のどれに必要か               |
| 汎用的なアイコン・バッジ       | 必要な意味を持ち、名称や状態と整合しているか |
| 流行の表現の追加               | IroMapの代表作業を改善する根拠があるか       |

2026年の動向から参照するのは独自の視覚ルールと編集された短い文言。
手描き風、紙の質感、巨大文字などを「人間らしさ」の必須条件にはしない。
IroMapらしさは、画像と色分布の対応、選択の表現、数値の扱いを揃えることから作る。

## 11. 品質基準とレビュー材料（提案）

### 11.1 アクセシビリティ

WCAG 2.2 AAを設計目標とする。以下の抜粋を満たすだけで準拠を宣言しない。

- 通常文字は4.5:1、大きな文字は3:1。適用対象と例外はWCAGの定義に従う。
- 操作の識別や重要な図形に必要な非テキスト表現は隣接色に対して3:1。装飾線すべてへの一律要求ではない。
- 操作と状態を色だけで伝えない。実際の色を示す色見本には値とラベルを添える。
- キーボードで主要作業を完了でき、フォーカスを見失わず、固定UIで完全に隠さない。
- 操作対象は原則24×24 CSS px以上、または規定の間隔・例外を満たす。タッチの主要操作は44×44を設計目標とする。
- ドラッグが必要な選択には代替手段を設計する。
- 320 CSS px相当や200%文字拡大で主要操作に到達できる。2D表示が本質的な図・表は例外の必要性を個別判断する。
- 処理と失敗を支援技術に伝える。ホバーやフレーム更新のたびに読み上げない。

### 11.2 レビューに用意するもの

1. 同じ画像・機能で比較した表現方向の候補と、判断理由。
2. 全体観察／領域選択／色確認／コピー／失敗復帰のワイヤーフレーム。
3. ライト／ダークの代表画面と、色・文字・数値・余白の基礎仕様。
4. 画像なし／分析中／結果あり／再計算／失敗／利用不可の状態例。
5. 共通・分析用部品の状態一覧と操作仕様。
6. 広い画面・狭い画面・キーボード・タッチでの動作確認。
7. 赤み・青み・低彩度・明暗の強い画像、極端に明るい／暗い画像、長い画像名、小数・欠損値の例。
8. UIテーマ変更で分析値と色見本が変わらないこと、選択と表示が対応することの検証。

### 11.3 方向性レビューの完了条件

- 利用者、中心となる問い、優先する代表作業を説明できる。
- 画面の主役と、基本操作・詳細情報の位置づけが一致している。
- 方針から具体的な部品・画面の判断を導け、トレードオフを説明できる。
- 状態、幅、入力方法、テーマが変わる場合の設計が存在する。
- 数値・対象・条件の意味が明確で、精度を過大に表現しない。
- 採用する表現、保留する表現、未確定事項が記録されている。

文書だけでは視覚品質の承認条件を満たさない。画面・部品の実例と検証結果が揃ってからAdoptedへ進める。

## 12. 未確定事項と、決める順序

| 順序 | 決めること                                                                     | 判断材料                                       |
| ---- | ------------------------------------------------------------------------------ | ---------------------------------------------- |
| 1    | 本人の写真から色方向を探る主要シナリオを確認し、他の利用者への適用範囲を決める | 作業・心理・必要情報の対応表                   |
| 2    | 3Dと断面の反復、写真と分析の補助経路を具体化する                               | 状態図と、同じ作業を行うワイヤーフレーム       |
| 3    | 表現方向、密度、文字・数値・面の階層                                           | 代表画面での候補比較                           |
| 4    | 色の具体値、テーマ既定値、選択表現                                             | 実画像と操作状態、コントラスト測定             |
| 5    | 部品の種類と状態、レスポンシブの規則                                           | 部品例・操作確認                               |
| 6    | Liquid Glass等の素材の採否                                                     | 不透明な基準案との比較、可読性・性能・代替表示 |
| 7    | 採用判断と既存UIの移行範囲                                                     | レビュー結果、要求との対応、影響範囲           |

並行して調査すること: 入力画像の色プロファイルと変換条件、各指標の分析対象、コピー結果に付ける条件情報、既存の永続化状態。
職種・利用頻度、複数画像比較の初期範囲、ブランドの最終表現、承認者は未確定。
